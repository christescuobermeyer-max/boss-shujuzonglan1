# Mobile Aftersales Filter Shop Count Design

## Goal

在手机端“售后每日工作”的四个人员筛选按钮中展示当前所选日期对应的店铺数量，同时保持现有日期筛选、人员筛选、记录明细和“运营接手店铺数”板块不变。

## Scope

- 调整 `全部 / 梁智 / 朱雯雯 / 冯姗姗` 四个筛选按钮的内容和高度。
- 新增一个纯函数，按筛选人员统计当日不重复店铺数。
- 不修改接口、请求参数、请求时机或后端代码。
- 不修改 `MobileWorkflowProgressSection` 和“运营接手店铺数”。

## Counting Rules

1. 统计数据来自当前日期接口返回的全部售后明细。
2. 人员归属沿用现有规则：优先使用记录自身的 `operatorName`，为空时继承外层人员名称。
3. 同一人员同一店铺出现多条售后记录时只统计一个店铺。
4. 店铺唯一标识优先使用非空 `merchantId`。
5. `merchantId` 为空时，使用去除首尾空格后的 `shopName` 作为备用唯一标识。
6. `merchantId` 和 `shopName` 均为空的记录不计入店铺数。
7. `全部` 对当前日期全部记录进行全局去重。同一店铺即使出现在不同人员名下，也只计一个店铺。
8. 三个人员按钮分别对该人员筛选后的记录去重统计。

## Interface

四个按钮保持单行四列。每个按钮调整为上下两行：

- 上方：强调显示店铺数量，例如 `12店`。
- 下方：显示筛选名称，例如 `朱雯雯`。

选中态继续使用现有黑底白字样式，未选中态继续使用白底边框样式。按钮使用固定高度和稳定的两行布局，确保 390px 和 430px 手机宽度下不横向溢出。

## Data Flow

1. `MobileAftersalesDailySection` 接收当前日期的 `daily` 数据。
2. 纯函数基于现有标准化、时间排序后的售后记录计算四个筛选项的店铺数。
3. 组件渲染筛选常量时，根据筛选值读取对应店铺数。
4. 点击按钮后仍只更新本地 `selectedPerson`，不新增接口请求。
5. 明细列表继续使用现有 `filterAftersalesRecords` 输出。

## Error And Empty States

- 加载、请求错误和明细空状态文案保持不变。
- 无数据时对应按钮显示 `0店`。
- 统计函数对缺失的 `employees`、`records`、`merchantId` 和 `shopName` 做容错处理。

## Testing

- 单元测试覆盖同一店铺多条记录去重。
- 单元测试覆盖跨人员的“全部”全局去重。
- 单元测试覆盖空 `merchantId` 时按 `shopName` 去重。
- 单元测试覆盖两种标识均为空时不计数。
- 布局源代码测试覆盖按钮内数量和名称的独立元素及对应 CSS 类。
- 完成后运行全量单测、TypeScript 检查和生产构建。
