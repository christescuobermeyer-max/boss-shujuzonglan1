# 售后每日工作人员筛选设计

## 背景

手机看板“售后每日工作”当前保留日期筛选，并同时展示售后人员统计卡片和所选日期的全部记录。随着记录数量增加，用户难以快速查看指定人员当天的全部工作明细。

本次仅调整“售后每日工作”板块。“运营接手店铺数”板块及其数据、接口、文案和布局不做任何修改。

## 目标

- 保留现有售后日期选择器和默认昨日逻辑。
- 新增 `全部`、`梁智`、`朱雯雯`、`冯姗姗` 四个人员筛选。
- 默认选择 `全部`。
- 点击人员后，仅展示该人员在所选日期的全部售后记录。
- 切换人员时不重新请求接口，直接筛选当前日期已经加载的 payload。
- 标题数量随当前筛选结果变化。
- 保持单条售后记录的店铺、动作、人员、平台、状态、备注和充值信息展示不变。

## 非目标

- 不修改 `/api/mobile/aftersales/daily-records` 请求参数。
- 不修改 Hono 后端和上游开放 API。
- 不修改“运营接手店铺数”或“运营工作进度”。
- 不增加人员管理、动态配置或权限控制。
- 不改变售后记录排序，继续按 `createdAt` 从新到旧展示。

## 交互设计

“售后每日工作”板块从上到下排列为：

1. 标题、更新时间和当前筛选结果数量。
2. 原有日期选择器。
3. 人员分段筛选栏。
4. 当前筛选的记录列表或空状态。

人员筛选使用紧凑的四列按钮，在手机宽度下保持单行等宽。当前选中项使用黑底白字，未选中项使用白底和浅色边框。按钮具备明确的 `aria-pressed` 状态。

切换日期时保留当前人员筛选。例如用户查看“朱雯雯”后修改日期，新日期加载完成后仍展示朱雯雯的记录；若当天无记录则显示空状态。

## 数据规则

筛选基于每条扁平化记录的有效人员名称：

1. 优先使用 `record.operatorName`。
2. 为空时继承外层 `employee.operatorName`。
3. 仍为空时归为 `未分配`。

`全部` 返回当前日期 payload 中的所有记录，不限制人员，也不截断数量。

指定人员使用姓名完全匹配：

- `梁智`
- `朱雯雯`
- `冯姗姗`

当前标题数量使用筛选后的记录条数，不使用接口顶层 `totalCount`，避免人员筛选后数字与列表不一致。

## 组件与辅助函数

在 `lib/mobile-work-boards.ts` 增加：

```ts
export const AFTERSALES_PERSON_FILTERS = [
  { value: "all", label: "全部" },
  { value: "梁智", label: "梁智" },
  { value: "朱雯雯", label: "朱雯雯" },
  { value: "冯姗姗", label: "冯姗姗" }
] as const;

export type AftersalesPersonFilter =
  (typeof AFTERSALES_PERSON_FILTERS)[number]["value"];

export function filterAftersalesRecords(
  payload: AftersalesDailyRecordsPayload,
  person: AftersalesPersonFilter
): AftersalesRecord[];
```

`filterAftersalesRecords` 复用现有扁平化和排序逻辑，`all` 返回全部记录，其他值按有效 `operatorName` 完全匹配。

`MobileAftersalesDailySection` 内部维护 `selectedPerson`，默认值为 `all`。当前已有的售后人员统计卡片网格移除，避免统计卡片和筛选按钮重复表达人员维度。

## 空状态

- `全部` 无数据：`所选日期暂无售后记录`
- 指定人员无数据：`该人员当日暂无售后记录`
- 加载和接口错误状态沿用当前实现

## 测试策略

- 单元测试 `全部` 返回当日所有记录。
- 单元测试三个指定姓名只返回对应记录。
- 单元测试记录人员为空时继承外层人员名称。
- 单元测试结果继续按时间倒序排列。
- 源码测试四个筛选文案、默认 `all`、`aria-pressed` 和日期筛选仍然存在。
- 源码测试“运营接手店铺数”相关代码未被修改。
- 运行完整 Vitest、TypeScript 和 Next.js 构建。
- 在 390px 和 430px 视口确认筛选按钮不换行、不溢出，记录内容无重叠。

## 验收标准

- 售后板块显示四个人员筛选且默认选中“全部”。
- 切换人员立即更新标题数量和全部明细列表。
- 切换日期继续使用原接口，并保持当前人员选择。
- 指定人员无数据时显示明确空状态。
- 单条记录展示字段和排序保持不变。
- “运营接手店铺数”没有代码、样式或行为变化。
- 手机页面测试、类型检查和生产构建通过。
