# 全部日期回款趋势设计

## 目标

在现有 BOSS 手机看板中新增“全部日期回款趋势”图表。后端从 MongoDB 云数据库聚合全部有效日期的每日总回款，前端默认展示完整历史走势，并支持缩放、拖动和最大化查看。

## 已确认决策

- 新图表是现有“每日回款趋势”的补充，不替换当前月度图表。
- 新增独立后端接口，避免把全量历史数据附加到月度接口。
- 图表只展示每日总回款，不拆分美团与饿了么趋势线。
- 默认展示全部历史数据，而不是默认截取最近 30 天或 90 天。
- 横轴和纵轴使用精简标签，完整日期和精确金额通过提示框查看。
- 提供最大化按钮，以全视口覆盖层展示图表。
- 排除最新一个可能尚未导入完整的日期，避免末尾出现误导性的回款暴跌。
- 新图表不受月度选择器影响，切换月份不重新请求全量趋势。

## 数据核对结论

2026-07-13 对云数据库进行了只读核对：

- `daily_point_details` 共 263,443 条明细。
- 美团 221,098 条，饿了么 42,345 条。
- `recordDateKey` 有效范围为 2025-01-27 至 2026-07-12，共 532 个连续日期。
- 未发现无效日期或缺失 `amountValue` 的记录。
- 2026-07-12 只有 275 条记录，明显少于此前每天约 1,000 条，属于可能未完整导入的最新日期。
- 现有 `fetchAllDailyPointAmountTrend()` 会按业务日期聚合、去重并移除最后一个日期，当前实际返回 531 个趋势点，范围为 2025-01-27 至 2026-07-11。

以上数量仅用于设计验证，不作为接口中的硬编码条件。接口始终根据数据库当前内容动态计算日期范围。

## 非目标

- 不修改现有月度回款统计公式。
- 不删除或替换现有“每日回款趋势”。
- 不增加美团、饿了么或城市拆分线。
- 不增加自定义日期筛选器。
- 不增加数据导出、截图下载或报表分享功能。
- 不修改 MongoDB schema，也不迁移已有数据。
- 不修改归档桌面端或 `desktop-tauri/`。

## 方案选择

采用独立全量趋势接口。

未采用的方案：

- 扩展现有月度接口：切换月份时会重复传输相同的全量历史数据，并使月度接口承担无关职责。
- 前端逐月请求再拼接：请求数量多、加载慢，并会把日期去重和口径一致性问题推给浏览器。

独立接口让全量趋势与月度看板保持清晰边界，前端进入页面时只需加载一次。

## 后端设计

### 路由

新增受现有 `mobileAuthMiddleware` 保护的接口：

```http
GET /api/mobile/stats/repayment-trend/all
```

该接口不接受月份参数或部门参数，返回数据库中全部有效业务日期的公司总回款趋势。

### 响应契约

```ts
type AllRepaymentTrendResponse = {
  startDate: string | null;
  endDate: string | null;
  points: Array<{
    date: string;
    value: number;
  }>;
};
```

约束：

- `date` 使用 `YYYY-MM-DD`。
- `value` 是当日美团与饿了么回款合计，四舍五入到两位小数。
- `points` 按日期升序排列。
- `startDate` 和 `endDate` 分别取返回点集首尾日期。
- 没有数据时返回空数组，`startDate` 和 `endDate` 均为 `null`。
- 接口不返回原始商户、店铺、运营人员或导入行数据。

### 聚合口径

复用 `server/boss-shuju/src/lib/stats/daily-point-monthly.ts` 中的 `fetchAllDailyPointAmountTrend()`，不重新实现一套统计公式。

现有聚合规则：

1. 只处理 `meituan` 和 `eleme` 平台。
2. 美团优先使用 `rowData.结算周期` 中最后一个日期作为业务日期。
3. 饿了么以及无法解析结算周期的记录使用 `recordDateKey`。
4. 使用平台、业务日期、商户 ID、店铺 ID、店铺名称和金额组成去重键，与现有月度趋势规则保持一致。
5. 按业务日期汇总两个平台的金额。
6. 金额保留两位小数，并按日期升序排列。
7. 移除聚合结果中的最后一个日期，将其视为可能未完整导入的最新日期。

### 服务与缓存

新增 `server/boss-shuju/src/services/all-repayment-trend-service.ts`，职责仅包括：

- 调用 `fetchAllDailyPointAmountTrend()`。
- 从结果中计算 `startDate` 和 `endDate`。
- 构造 `AllRepaymentTrendResponse`。
- 使用现有 `report-cache.ts` 保存三分钟内存缓存。

缓存使用独立 namespace `all-repayment-trend` 和固定 key `all`。缓存只降低重复聚合成本，不改变数据库数据和接口语义。

### 错误处理

- 未登录请求由现有认证中间件返回 `401`。
- MongoDB 连接或聚合失败时返回 `500`。
- 错误响应使用通用中文消息 `获取全部日期回款趋势失败`。
- 后端日志和响应不得暴露 MongoDB URI、原始明细或环境变量。

## 前端设计

### 数据加载

在 `lib/mobile-api-client.ts` 中增加全量趋势 URL 构造函数，在 `lib/mobile-contracts.ts` 中增加响应类型。

新建 `components/mobile/mobile-all-repayment-trend.tsx`，独立负责：

- 页面首次渲染后的接口请求。
- `credentials: "include"` 认证请求。
- `401` 时跳转 `/mobile/login`。
- 加载、成功、空数据和错误状态。
- 普通与最大化状态切换。
- 打开最大化时锁定页面背景滚动，关闭或卸载时恢复滚动。
- 监听 `Escape` 关闭最大化层。

该组件挂载后请求一次。月度选择器变化不会改变组件 key、请求 URL 或 effect 依赖，因此不会重复加载。

### 页面位置

在 `components/mobile/mobile-boss-dashboard.tsx` 中，将新模块放在：

1. 现有“每日回款趋势”之后。
2. 现有“每日开单趋势”之前。

标题为 `全部日期回款趋势`。副标题在有数据时显示实际范围，例如 `2025-01-27 至 2026-07-11`。

### 普通图表

在 `components/mobile/mobile-boss-charts.tsx` 中新增专用全量趋势图表组件，保留现有月度图表行为不变。

普通状态要求：

- 默认绘制接口返回的全部点。
- 高度约 220px，并保持稳定尺寸。
- 单条折线，不显示每个数据点的 symbol。
- 横轴按数据密度稀疏显示月份或关键日期，并启用 `hideOverlap`。
- 纵轴金额使用 `万`、`千` 等紧凑格式。
- 提示框显示完整日期和 `¥` 金额，金额保留两位小数并带千位分隔符。
- 支持触摸拖动和双指缩放。
- 提供紧凑的缩放条，让用户了解当前观察范围并快速移动。
- 图表不得因为标签、提示框或缩放控件撑破手机页面宽度。

### 最大化交互

项目当前没有图标组件库。实现时增加 `lucide-react` 依赖，标题右侧使用 `Maximize2` 图标按钮，最大化层使用 `X` 图标关闭按钮，不使用文字胶囊按钮或手绘 SVG。按钮必须具有：

- `aria-label="最大化全部日期回款趋势"`。
- 可见焦点状态。
- 桌面悬停提示。

点击后使用固定定位覆盖层占满浏览器视口。采用应用内全视口层，而不是依赖浏览器 Fullscreen API，以避免移动浏览器权限、地址栏和手势兼容性差异。

最大化状态要求：

- 顶部显示标题、日期范围和关闭图标按钮。
- 图表填满剩余可用高度。
- 保留提示框、拖动、双指缩放和缩放条。
- 设备横竖屏切换或视口尺寸变化后，ECharts 自动 resize。
- 点击关闭按钮或按 `Escape` 返回普通状态。
- 打开时锁定背景滚动，关闭和组件卸载时可靠恢复。
- 覆盖层位于所有现有移动看板内容之上，且不发生文字或按钮重叠。

### 状态展示

- 加载：显示与最终图表高度接近的骨架区域。
- 空数据：显示 `暂无全部日期回款数据`。
- 请求失败：显示 `全部日期回款趋势暂时无法加载`。
- 新接口失败不能隐藏、阻塞或清空现有月度看板数据。

## 性能

- 聚合在 MongoDB 内完成，浏览器只接收约数百个 `{date, value}` 点。
- 沿用聚合的 `allowDiskUse(true)`，避免较大数据集排序和分组时受内存限制。
- 使用现有三分钟缓存，降低多用户或重复打开页面造成的数据库扫描。
- 前端只绘制一条无 symbol 折线。
- 图表组件使用稳定尺寸，进入最大化和视口变化时才执行必要的 resize。
- 当前约 531 个点不需要分页、抽样或额外依赖；未来数据量明显增长时再评估服务端降采样。

## 测试策略

### 后端单元与源代码测试

- 新路由存在并使用 `mobileAuthMiddleware`。
- 新路由连接 MongoDB 并调用独立服务。
- 服务为空数组时返回 `startDate: null`、`endDate: null` 和空 `points`。
- 服务有数据时正确取首尾日期，不改变点的升序顺序和金额。
- 聚合保留业务日期解析、去重、两位小数和排除最后日期规则。
- 缓存 namespace 与月度统计隔离。

### 前端测试

- URL 构造函数生成 `/api/mobile/stats/repayment-trend/all`。
- 新组件使用 `credentials: "include"`。
- `401` 跳转登录页。
- 组件不依赖月度选择器值，月度切换不重复请求。
- 页面包含 `全部日期回款趋势`，并位于月度回款趋势与每日开单趋势之间。
- 普通图表包含稀疏横轴、紧凑金额轴、tooltip 和 dataZoom 配置。
- 最大化与关闭按钮有正确无障碍名称。
- 覆盖层支持关闭、`Escape`、背景滚动锁定与恢复。
- 加载、空数据和失败状态文案存在。

### 验证命令

- 根目录运行 `npm run typecheck`。
- 根目录运行 `npm run test:unit`。
- 运行 `npx tsc -p server/boss-shuju/tsconfig.json --noEmit`。
- 使用云数据库进行一次只读接口验证，确认点集非空、日期升序、末日为最近完整日期。
- 使用浏览器在 390px 和 430px 视口验证普通图表、最大化图表、缩放、关闭和无横向溢出。

## 验收标准

- 登录后打开 `/mobile` 可以看到新的“全部日期回款趋势”。
- 图表位于现有月度回款趋势之后、每日开单趋势之前。
- 图表默认包含数据库内全部历史完整日期的每日总回款。
- 当前云库下，返回范围应动态对应约 2025-01-27 至最近完整日期；不得硬编码日期或点数。
- 最新一个可能未完整导入的日期不会出现在结果中。
- 横轴和纵轴标签在手机宽度下保持精简且不重叠。
- 点击或触摸图表可查看完整日期和精确金额。
- 用户可以拖动、缩放并通过最大化按钮全视口查看。
- 最大化层可以通过关闭按钮和 `Escape` 退出，退出后页面滚动正常恢复。
- 切换月份不会重新请求或改变全部日期趋势。
- 新接口或新图表失败不会影响现有月度数据和其他看板模块。
- 所有现有测试、前后端类型检查和新增测试通过。
